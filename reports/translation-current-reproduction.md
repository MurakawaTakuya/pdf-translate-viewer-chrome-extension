# 現行ビューアのGemini対応ずれの再現

記録日時: 2026-11-01T16:41:33+0900（JST）
事前計画日時: 2026-11-01T16:34:55+0900（JST）

## 結論

**現行コードの送信内容を変更せず3回実行し、3回とも原文ブロックと訳文の対応ずれを再現した。** R1とR2では、ユーザーが指摘した「左段の本文に、右段へ続く別ブロックの内容が結合され、その後の訳文が前のIDへ割り当てられる」現象をAPIの生の応答で確認できた。R3は同じ場所のずれ方が異なったが、6ページ目の対応は大きく崩れた。

少なくとも今回の具体的な崩れは、訳文の長さに合わせて表示側が段落を数え直しているためではない。**表示処理に渡す前のJSONで、既に内容とIDが食い違っていた。** ただし、他の表示上の問題もすべて同じ原因だと証明するものではない。

## 条件と実行範囲

- 対象: https://arxiv.org/pdf/2301.08243 、17ページ。再取得したPDFは従来の検証PDFとSHA-256が一致した。
- 通常のビューアのコード: コミット `3d462cd`。共有の `pdf-layout.js` で抽出した217対象。元の282対象の抽出は使っていない。
- 通常の `createGeminiTranslator` から送信JSONを直接取得した。`inputFormat` を上書きせず、現行の既定であるページ内ブロック＋文書全体の連番IDを使う。評価専用の参照／対象分離形式は使っていない。
- モデル: `gemini-3.5-flash-lite`。全文を1リクエスト、訳文のみを出力。`/v1beta/interactions`、`stream:true`、`store:false`、`max_output_tokens:65536`。
- LangTalkの既存キーを、許可されたGoogle Cloud CLI認証経由でプロセスのメモリにだけ取得した。既定の別プロジェクトは使わず、キー作成・API有効化・課金設定変更はしていない。秘密値をファイル・ログ・Gitに保存していない。
- R1 → R2 → R3の最大3回を事前固定し、同じ送信JSONを3回実行。再試行・修復生成・追加の判定モデル・結果を見てのプロンプト修正は0回。
- ブラウザーでの表示再現ではなく、同じ抽出・同じモデル・同じリクエストによる応答の再現確認。ChromeのUIは操作していない。

ID8と13の間には、連絡先の脚注、グラフのタイトル・軸ラベル、Figure 1の説明がある。入力上は別々の対象だが、意味として続く本文をモデルが結合した。R1/R2では、ID8の原文にない引用番号[11]と音声への一般化の記述がID8の応答に入り、元々それを含むID13に次の段落が入ったことも確認した。

R3はID13の最初の文の続きだけがID8へ入った。ID13にはその後の分類・音声の文が残り、ID14–20はこの場所でR1/R2のように1件ずつずれていない。**同じ入力でもずれ方は一定ではなく、単純にIDへ一定数を足す補正はできない。**

6ページ目でも別原文との対応ずれが確認できた。

- R1: ID80のTable 3説明にTable 5説明、ID84のLocal Prediction Tasks見出しに本文が入った。
- R2: Table 3/4の説明の話題は対応していたが、ID82のLow-Shot段落に次のTransfer learning段落、ID84の見出しに本文が入った。
- R3: ID80のTable 3説明にScalability見出し、ID84の見出しにTable 5説明、ID91のTable 4説明にプレディクタの役割を説明する本文が入った。

引用番号の過不足の自動診断は1–8ページでR1=65、R2=52、R3=49箇所。これは確認候補を拾う補助であり、誤訳件数・ずれ率・意味対応の合否とは扱わない。

## 入力と表示のどこが関係するか

現在のブロックはPDF上の位置から作るため、論理的に1つの段落でも列やページをまたぐと分かれる。キャプションや脚注・図ラベルも別ブロックとしてその間に入り得る。送信指示には結合・分割・省略を禁じる指定があるが、モデルが守ることをJSONスキーマだけで保証できない。

表示側は返されたIDを元の固定座標へ対応させる。訳文の長さで後続IDを振り直す処理はない。長い訳文は縮小や縦方向のはみ出しを起こし得るため、誤った結合が起きると見た目も悪化する。今回確認した別段落の訳が別の枠に入る問題は、その前段の生成応答から既に存在する。

ローカル翻訳はアプリ側が各対象の呼び出しと返答の対応を保持する。一方、現行のGemini全文翻訳は生成モデルに多数のIDと内容の対応も返させている。この違いが今回の現象と整合する。入力整理だけで解決済みとは言えず、表示のフォントサイズ調整だけでも直らない。
