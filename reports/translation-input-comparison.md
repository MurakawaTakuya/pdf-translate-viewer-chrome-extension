# 段落抽出とGemini入力分離の検証

記録日時: 2026-11-01T01:46:14+0900（JST）
事前計画日時: 2026-11-01T01:38:03+0900（JST）

## 結論と最終実装

段落抽出の改善は実装した。PDF内部の描画順に依存せず座標から行・列の読み順を組み立て、太字を含むキャプションやインライン見出しを通常書体の本文から分断しない。複合語のハイフンを失わないよう、語中改行ではハイフンを保持する。同じ論文の翻訳対象は282件から217件になった。

全文の参照ページと翻訳対象一覧を分ける方式も実装して実生成したが、安定しなかった。**入力分離を通常のビューアの既定にしない。** `inputFormat: 'separate-targets'` の明示指定がある評価ツールだけで使う。通常のビューアは抽出改善を有効にし、送信形式は従来の番号付きブロックを維持する。全文1リクエスト、訳文のみの出力、ストリーミング、手動の不足分補完を維持する。

段落分断に由来する表示枠の問題は局所テストで修正できたが、**Geminiの生成内容とIDの対応ずれが解決したとは言えない。** 今回の4回には「抽出だけ改善し、従来の送信形式を使う」独立した実生成群は含めていない。その組み合わせの生成精度は未検証であり、改善方式Cの結果をそのまま帰属させない。

## 比較条件

- 対象: [arXiv:2301.08243](https://arxiv.org/pdf/2301.08243)、同じローカルPDFの17ページ。
- モデル: `gemini-3.5-flash-lite`。承認済みのLangTalk側の既存の拡張機能用キーをgcloudからメモリ内だけに取得。認証情報はファイル・ログ・Gitに保存していない。
- A: 元の抽出282件と、コミット `51e7ec1` の送信形式。送信JSONのSHA-256は前回のAと完全一致する。
- C: 座標による読み順、混在書体の段落結合、ハイフン保持、段落種類のヒント、参照全文と対象一覧の分離をまとめて変更。対象217件。個々の変更の効果は切り分けていない。
- Cの参照ページは全文テキスト、対象一覧は番号・ページ・種類・正確な原文を持つ。原文が両方に含まれることを指示し、対象一覧だけを翻訳させる。原文を出力させる指示はない。
- 両方式とも `/v1beta/interactions`、`stream:true`、`store:false`、`max_output_tokens:65536`。出力スキーマは同じ小さな固定スキーマ。翻訳品質の指示は共通。
- 順序は事前固定の **A1 → C1 → C2 → A2**、最大4回、実際4回、再試行0回。結果を見たプロンプト修正や追加生成は行っていない。
- 前回固定した20箇所を、新しい抽出の同じ原文を含む段落へ事前に対応付けた。全文を出力するキャプションとインライン見出しは、結合後の段落全体の範囲で読んだ。

## 件数以外の対応確認

固定20箇所の人手確認。盲検・独立評価ではなく、全文の翻訳品質スコアでもない。

- A1: 明確に別の原文の内容が入った箇所を3件確認。Table 3キャプション先頭に `I-JEPA`、Local Prediction Tasks見出しに本文、Table 4先頭にDINOを含む表ラベルが入った。
- C1: 明確な別原文への対応ずれを10件確認。2ページ目で次段落へずれ、6ページ目ではTable 3のキャプションにScaling data sizeの本文、Local Prediction Tasks見出しにFigure 5のキャプションが入った。
- C2: 固定20箇所では明確な別原文への対応ずれは見られず、Table 3 / Table 4の結合後キャプションもその原文の範囲に対応した。ただしタイトルと2箇所のグラフ軸ラベルが英語のままだった。件数の成功を完全な翻訳品質とは扱わない。
- A2: 固定20箇所で別原文への対応ずれを16件確認。Table 3先頭が `4`、Low-Shot見出しが `54.2`、Local Prediction Tasks見出しが `0.25` になるなど、IDの存在だけでは判別できない崩れが残った。

C1では不足16件があり、C2は構造検査を通ったが未翻訳を含む。安定した対応を必要とする用途の既定としては採用できないため、Cは評価専用にした。IDをコピーする生成自体に依存する限り、入力を整理しても対応ずれを完全には防げない、という今回の観測と整合する。全モデル・全論文に一般化するものではない。

## 抽出側の確認と検証範囲

`pdf-layout.js` を通常のビューアとオフライン抽出で共有した。混在書体のTable 3 / Table 4は先頭と本文が結合し、元の1行8.12 ptの枠から6行62.92 ptの枠になった。短い先頭枠に全文が押し込まれる原因を除去した。

座標からの読み順は列間の空白と全幅要素の上下の空白を再帰的に分割して推定する。複雑な表・狭い列間・変則レイアウトの読み順を完全に保証するものではない。段落種類も推定であり、出力内容を保証しない。
