# PDF翻訳ビューア

論文PDFを、原文の図・数式・段組みを残しながら翻訳して読むChrome拡張機能です。

このリポジトリは、[kobayashi-31/pdf-translate-viewer-chrome-extension](https://github.com/kobayashi-31/pdf-translate-viewer-chrome-extension) をforkし、村川卓也（[MurakawaTakuya](https://github.com/MurakawaTakuya)）が独自の変更を加えたものです。元の翻訳ビューアをベースに、Geminiの全文翻訳・途中表示、ツールバー、引用表示、原文の文字選択、元URLを維持する表示などを追加・改善しています。

![英語の論文、開いた瞬間 日本語に。](docs/01-cover.png)
![原文と訳文を並べて表示](docs/02-before-after.png)

画像には旧UIが含まれます。現在の操作は以下を参照してください。

## 主な機能

- Chrome内蔵のローカルAIと、Gemini APIの翻訳ボタンを個別に用意。
- PDFを開いたとき、既定ではローカルAIで日本語へ自動翻訳。設定でOFFにできます。
- 原文のみ・両方・翻訳後のみの表示切り替え。
- 原文・訳文の文字選択とコピー、対応ブロックの枠線による強調表示。
- ページ移動、倍率調節、幅・高さへのフィット、固定ツールバー。
- 原文・翻訳後・原文と訳文をページごとに交互に並べたPDFの保存。
- MLA・APA・ISO 690の引用表示とコピー、BibTeX・RISの出力。
- 対応Chromeでは元のPDF URLを維持し、アドレスバーから共有用のリンクをコピーできます。
- タブ名とヘッダーに原文の論文タイトルを表示します。PDFのメタデータを優先し、なければ既存の引用情報の先読み結果を使います。取得できなければファイル名を表示します。長いヘッダーは省略し、マウスを乗せると全文を確認できます。

## 動作環境とインストール

パソコン版Google Chrome 138以降。ローカルAIの利用可否は、ChromeのTranslator APIと選択した言語ペアの対応状況によります。初回は翻訳モデルのダウンロードが必要になる場合があります。スマートフォン版には対応していません。

1. [最新のRelease](https://github.com/MurakawaTakuya/pdf-translate-viewer-chrome-extension/releases/latest) の添付ファイル `pdf-translate-viewer-vX.Y.Z.zip` をダウンロードして展開します。GitHub自動生成の「Source code」ではなく、この配布用ZIPを使ってください。開発する場合はこのリポジトリをcloneしても使えます。
2. `chrome://extensions` を開き、「デベロッパー モード」をONにします。
3. 「パッケージ化されていない拡張機能を読み込む」から、`manifest.json` のあるフォルダを選びます。
4. PDFを開きます。拡張機能を読み込んだフォルダは削除・移動しないでください。

### インストール済みの拡張機能を更新する

1. 最新のReleaseから配布用ZIPをダウンロードして展開します。
2. 現在Chromeに読み込ませているフォルダへ、展開したフォルダの中身を上書きします。読み込み元のフォルダ名・場所は変えません。
3. `chrome://extensions` で「PDF翻訳ビューア」の再読み込み（丸い矢印）を押します。
4. PDFの元URLを開き直します。タブ内の翻訳結果は引き継がれません。

開発用にcloneしたフォルダから読み込んでいる場合は、ZIPの上書きではなく、そのフォルダのコードを更新してから手順3・4を行ってください。

**PDFタブの更新だけでは、新しいmanifestやバックグラウンド処理は反映されません。** 既に開いている `viewer.html?file=...` のタブは自動移行しません。

### 元のPDF URLを維持する表示

[MIMEハンドラAPI](https://developer.chrome.com/docs/extensions/reference/api/mimeHandler) が利用できるChrome 151以降では、自動表示時に `https://arxiv.org/pdf/2301.08243` などの元URLを維持したまま拡張ビューアが開きます。Chromeが受信したPDFをそのまま読み込み、元URLへもう一度取得しに行きません。

次の場合は従来の `chrome-extension://…/viewer.html?file=…` 形式を使います。

- MIMEハンドラAPIを利用できないChrome。
- 拡張アイコンの「このPDFを翻訳ビューアで開く」で、明示的にこのビューアを選んだ場合。他のPDF拡張が優先されていても切り替えられるようにするためです。

複数の拡張機能がPDFハンドラを登録している場合、自動表示にはChrome側の優先順位が適用されます。ローカルの `file://` PDFを従来形式で開く場合は、Chromeのバージョンにかかわらず、拡張機能の詳細で「ファイルのURLへのアクセスを許可する」をONにしてください。MIMEによる自動表示にはこの設定は不要です。

ローカルPDFを元URLのまま表示している場合、タブ名へのタイトル反映には「ファイルのURLへのアクセスを許可する」が必要です。論文タイトルは翻訳せず、PDFの保存名は元のファイル名を使います。タブ名のためにGeminiを呼び出すことはありません。

### 通常のビューアへ切り替える・翻訳ビューアへ戻す

ファイル名の横のアイコンを押すと、そのPDFを通常のビューアで開き直します。切り替え先を選ぶメニューはありません。

- Google Scholar PDF Readerが有効で、そのPDFへのアクセスが許可されていればScholarで開きます。
- Scholarが未導入・無効ならChrome標準で開きます。ほかのPDF拡張が有効な場合は、その拡張が表示されることもあります。
- ScholarからChrome標準へ移る場合は、Scholarの「その他」メニューにある「Chromeビューアで開く」を使えます。

ページ番号などを保持し、自動表示設定は変えません。同じタブ・同じPDFでは、更新しても通常のビューアでの表示を維持します。PDFを再取得するため、POSTや使い捨てURLの文書では切り替えできない場合があります。

**翻訳ビューアへ戻すには**、Chrome右上の拡張機能メニューから「PDF翻訳ビューア」を開き、「このPDFを翻訳ビューアで開く」を押してください。URL末尾を消すだけではタブ内の選択は解除されません。

## 翻訳する

1. PDFを開くと、既定ではローカルAIによる日本語訳が始まります。
2. 言語を変える場合は、右上で原文・訳文の言語を選びます。原文言語は自動検出ではありません。
3. 「ローカルAI」「Gemini」で翻訳方法を選びます。準備・翻訳中は実行中のボタンがローディング付きの「中断」に変わります。同じボタンで中断、もう一方のボタンで現在の処理を中断して切り替えられます。

中断すると先読みも止まり、スクロールだけでは再開しません。ローカルAIで完成した訳文は残し、未検証のGemini途中表示は切り替え前の有効な訳（なければ原文）へ戻します。中断前の処理が遅れて応答しても表示へ反映しません。再度翻訳ボタンを押すと新しい翻訳処理を始めます。

同じ言語ペアで翻訳方法を切り替えると、現在の訳文を残し、新しい訳が完成したブロックから差し替えます。別の言語ペアへ変える場合は以前の訳を消します。Geminiの暫定表示が検証エラーになった場合は、切り替え前の訳があれば戻し、なければ原文を表示します。

段落にマウスを乗せると原文・訳文の対応箇所を枠線で示します。「原文を表示」でそのブロックだけ訳を隠せます。Geminiの翻訳完了後は「訳し直す」で再翻訳できます。再翻訳中は今の訳を表示したまま、完成した新しい訳へ切り替えます。同じ文の数値と単位に分断された一部の断片は、引用の重複を防ぐため組全体を再翻訳・更新します。

APIキーを設定していれば、翻訳前やローカルAIの使用中も、段落にマウスを乗せると「Geminiで翻訳」が表示されます。通常は対象と前後最大2段落を文脈として送り、その段落だけを生成します。周辺の読み取りは対象ページと前後1ページ以内に絞り、遠いページの抽出完了を待ちません。文脈が足りない場合は「全文を添えて翻訳」または「全文を添えて訳し直す」を押すと、全ページを参照して対象だけを新しく生成します。全文付きへの自動切り替えは行いません。数値と単位など検査を共有する断片は一緒に翻訳します。他の段落のローカル翻訳は続け、対象の訳はGeminiの結果ができてから差し替えます。処理中は同じボタンで中断できます。同じモデル・言語の取得済みGemini訳はタブ内で再利用し、表示中のGemini訳を「Geminiで訳し直す」と追加生成します。

図表のキャプションは翻訳し、判定できた図表内のラベル・軸名・表のセルは原文のまま残します。参考文献一覧も翻訳せず、後続の付録本文から翻訳を再開します。ローカルAI・Gemini共通の動作です。PDFの描画領域・罫線・見出しから判定するため、罫線のない表や特殊な配置では識別できない場合があります。除外した原文も文字選択でき、Geminiの全文文脈には残ります。

### 2つの自動設定

| 設定場所 | 設定 | OFFにした場合 |
|---|---|---|
| 拡張アイコンのポップアップ | PDFを自動で翻訳ビューアで開く | PDFを通常のビューアで開きます。アイコンにOFFと表示します。 |
| ビューア右上の設定 | PDFを開いたときに自動翻訳 | 拡張ビューアは開きますが、翻訳ボタンを押すまで翻訳しません。 |

自動翻訳の設定は次にPDFを開いたときから反映されます。自動表示がOFFでも、拡張アイコンからそのPDFだけを手動で開けます。ファイル名の横のアイコンから通常のビューアへ切り替えられます。

### ローカルAI

ChromeのTranslator APIでブロックごとに翻訳し、PDF本文を外部の翻訳APIへ送りません。APIキーは不要です。表示中のページと、その先15ページまで先読みし、スクロール先のページを優先します。翻訳後PDFを保存する際は、残りのページも同じローカルAIで翻訳します。

### Gemini

右上の設定で [Google AI Studio](https://aistudio.google.com/apikey) のAPIキーとモデルを保存し、「Gemini」を押します。既定モデルは `gemini-3.5-flash-lite` で、保存済みのモデル設定は維持します。設定の保存だけでは翻訳を始めません。

全ページから抽出したテキストを文脈として送り、通常は1つのPDFを1回のリクエストで翻訳します。大きい論文は翻訳対象を複数のまとまりに分け、各回に全文の文脈を付けて順番に送ります。分割番号は進捗に表示します。PDFファイルやページ画像そのものは送りません。1ブロック分の訳が完成したところから表示し、未完成の部分は現在の表示を保ちます。エラー時にローカルAIへ自動で切り替えることはありません。

分割の目安は1回128対象・スキーマ80,000バイトで、Googleの保証する上限ではありません。数値と単位など、引用検査を共有する一部の断片は同じまとまりに残します。スキーマの複雑さを理由とする400では最大2回まで追加分割します。分割数に応じてAPIリクエスト数と総入力トークンが増えます。

各対象に短い不規則なキーを付け、出力スキーマの必須項目として、そのキーに対応する原文と翻訳指示を指定します。受信時にキーの網羅性・重複・空欄・形式・API完了状態を検証し、数値の角括弧による参照番号と、検出できた未翻訳の英語見出し・図注も確認します。不一致のブロックは表示を保留し、有効な訳をタブ内に保持します。

問題が残ると「不足N段落だけ再翻訳」を表示します。この明示操作で、全文の文脈と対象だけを追加送信し、多ければ分割します。エラー欄の「問題のNブロックを確認」を開くと、ページ・対象ブロックの順番・理由・原文・保留した訳文を確認し、そのページへ移動できます。保留訳は完成した翻訳ではありません。「訳し直す」は通常、対象と前後最大2段落の文脈を添えた追加リクエストです。「全文を添えて訳し直す」を選ぶと、全文を文脈として送ります。途中切れや不正な応答を自動修復する処理はありません。429や一時的なサーバーエラーでは、待って最大6回再試行することがあります。

参照番号やキーが一致しても、意味の対応や翻訳の正しさは保証できません。原文と照合して利用してください。翻訳品質の検証結果と不採用の候補は、末尾の[翻訳方式の検証記録](#翻訳方式の検証記録)にまとめています。

無料枠・料金・データの取り扱いは、利用するプロジェクト・モデルとGoogleの利用条件に従います。ローカルAIの翻訳とGeminiへの送信は別の処理です。

### 翻訳結果の再利用

スクロールや同じタブでのPDF保存では取得済みの結果を再利用します。Geminiは同じ生成結果を表示と保存で共有し、これらの操作だけでは追加生成しません。

Geminiの検証済みの訳はタブ内にモデル・言語ペアとともに保持します。途中で中断・失敗しても確定分は残し、同じ条件で翻訳を再開すると残りだけを送ります。モデルや言語が変われば以前の結果を使い回しません。ブロックの「訳し直す」は明示的な追加生成です。

翻訳結果はタブのメモリに保持し、永続保存はしません。タブの更新・閉じ直しで失われます。翻訳ボタンの押し直し、言語の変更、手動の訳し直し・不足補完は新しい翻訳処理になります。APIキー・モデル・自動翻訳設定は拡張の保存領域へ、言語・表示方法・倍率はlocalStorageへ保存します。

## 読む・選択する・保存する

ツールバーは、左がファイル名、中央が表示切り替え・ページ移動・倍率・保存・引用、右が言語・翻訳・設定です。横スクロールやPDFの拡大中も画面上端に固定されます。

| 操作 | 動作 |
|---|---|
| 前後の矢印・ページ番号 | ページ移動。番号入力後にEnterでも移動できます。 |
| ＋・−・倍率表示 | 拡大・縮小・100%へ戻す。 |
| 幅／高さに合わせる | ツールバーを除いた表示領域へフィット。対訳の幅合わせは左右2ページが基準です。 |
| Cmd/Ctrl＋＋・−・0、ピンチ／Ctrl＋ホイール | ヘッダーを拡大せず、PDF部分の倍率を変更します。 |
| 原文・訳文のドラッグ | 文字を選択してコピーできます。原文はPDFに埋め込まれた文字情報を使います。 |
| 保存アイコン | 翻訳前の原文・翻訳後・原文と訳文を交互、の3方式から選べます。 |

ピンチ中は現在の画像を拡大縮小し、操作が止まってから高解像度で描き直します。左右の余白がある間は中央を保ち、余白がなくなるとポインター位置を基準に拡大します。倍率変更では翻訳APIを呼びません。

ツールバー下端の青い線はPDFデータの受信割合を示します。総サイズが不明なときは移動表示、受信後の準備中は点滅し、最初の描画が終わると消えます。通常の進捗・エラーはツールバー直下に表示します。

原文は翻訳前でも保存できます。翻訳後・交互の保存は、有効な翻訳結果がある場合に選べます。Geminiの未完了・不足・検証エラー時は無効です。保存だけを理由にGemini翻訳を始めることはありません。原文の保存は元PDFのバイト列を使います。

## 引用を表示する

引用ボタンからMLA・APA・ISO 690の引用を表示・コピーできます。BibTeXはフィールドごとに改行して表示し、コピー・保存できます。EndNote・RefMan・RefWorksで取り込めるRIS形式にも対応します。パネルや設定画面は外側のクリック・Escで閉じます。

書誌情報が届いた時点でタイトル・取得元・エクスポートを表示し、3種類の引用文は取得できた順に使えるようになります。照合済みのCrossref情報は再取得を省きます。取得がすべて成功したパネルは、同じタブで閉じて開き直しても待ち表示へ戻しません。初回の実際の待ち時間は外部の書誌サービスに依存します。

PDFのURL・メタデータ・先頭ページにあるDOI／arXiv IDから公開書誌情報を取得します。arXivの出版版はタイトルと先頭著者が一致する候補が1件だけの場合に使用し、それ以外はarXiv版を使います。取得元を確認でき、識別子の手動指定も可能です。「Google Scholarで確認」はタイトルの検索結果を開きます。Scholarの表示と引用スタイルや書誌データが異なる場合があります。

URLからarXiv／DOIを特定できる公開PDFは、読み込み後に書誌情報と3形式を先読みします。先読みが完了する前に押すと残りの取得を待ちます。ローカルファイルや識別できないURLは引用ボタンを押してから照会します。照会に識別子や公開されたarXivのタイトルを使いますが、PDF本文・Cookie・Gemini APIキーは送らず、Geminiのquotaも使いません。取得済みの書式は同じタブ内で再利用します。

## 既知の制約

- GeminiのIDと内容の対応は保証できません。検証成功は翻訳内容の正しさを保証しません。
- PDFの段落・読み順は座標からの推定です。複雑な表・段組みや、列・ページを跨ぐ本文では分断されることがあります。
- 長い訳文は文字が縮小されたり、ブロックの下へはみ出す場合があります。
- 文字情報のない画像PDFにはOCRを行わないため、文字選択・翻訳はできません。
- APIや言語ペアの対応状況によってはローカルAIを利用できません。
- PDF保存中は翻訳ボタンでの中断・切り替えを無効にします。段落の訳し直しを含む、PDF作成中の翻訳状態全体の固定は未実装です。

## 開発時の確認

ビルド不要のJavaScript ES modules構成です。開発用ツールとテストはNode.js 24を使います（`.nvmrc`）。Chromeでの利用にNode.jsは不要です。

```sh
npm ci
npm run check         # lint・整形確認・オフラインテスト
npm run format        # 整形を適用
npm run lint:fix      # 自動修正できるlint指摘を修正
npm test              # オフラインテストだけ実行
```

ESLintは推奨ルールを使い、拡張機能のブラウザAPIとNode.jsのテスト・検証スクリプトを分けて検査します。Prettierは個人テンプレートと同じ2スペース・セミコロンあり・ダブルクォート・80文字幅です。第三者の `lib/`・フォント・ライセンスと、過去の実験記録 `reports/` は対象外です。Markdownは既存の書式を保持します。

GitHub Actionsはmainへのpushとmain向けPRで `npm ci`・lint・整形確認・テストを実行します。開発依存はlockfileと固定バージョンで管理しています。minimatchは開発ツールの推移依存に既知のDoS問題（GHSA-g3hv-75wg-m249）があるため、修正版11.0.1をoverrideしています。上流の対応後にこのoverrideを見直してください。

翻訳ストリーム・取消・不足補完・エンジン切り替え・描画制御・URLルーティング・原文選択レイヤー・引用・設定をオフラインでテストします。テストコマンドは実際のAPIキーや無料枠を使いません。Chrome上の実描画やTranslator APIの動作は別途確認が必要です。

実APIでの検証ツールは [scripts/evaluation/README.md](scripts/evaluation/README.md) を参照してください。これらも既定は送信せず、明示した実行オプションでのみ生成します。評価ツールの明示的な実API実行は通常のlint・CIには含めません。

### 翻訳方式の検証記録

品質の検証は継続課題です。現行方式で論文の翻訳完了を確認していますが、キーや参照番号の検査は翻訳内容の意味一致を保証するものではありません。完全な意味一致を求める追加実験はいったん区切っています。

<details>
<summary>方式ごとの検証結果を開く</summary>

- [従来方式の再現](reports/translation-current-reproduction.md)：別IDへの内容の代入を確認。
- [短いキーによる方式の検証](reports/keyed-translation-evaluation.md)：確認した36箇所の対応ずれは改善。ただし、この検証では引用の欠落が残り、1回の手動補完でも全対象の有効な完成には未到達。
- [原文数式・引用を保護する候補](reports/protected-translation.md)：タグ欠落とモデル名の誤変換が残り不採用。表示・保存処理は検証用として残し、既定の翻訳には未適用。
- [構造化ノード方式](reports/node-translation.md)：最初のリクエストがHTTP 400で拒否され、翻訳品質は未評価・未採用。数式の上線と本体の分断、上付き文字の配置基準は別途修正。
- [改行・順位を文字列に埋める方式](reports/compact-node-translation.md)、[本文中のタグから原文を復元する候補](reports/atom-tag-translation.md)：内容の欠落などが残り不採用。試験用の方式は既定の翻訳には未適用。
- [引用番号の指定・目印方式の比較](reports/citation-experiments.md)：引用の欠落や順序・書式の不一致が残り不採用。数式の分断やJSONエスケープによる破損も記録。

</details>
